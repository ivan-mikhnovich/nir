# Автоматическое отображение между таксономиями

Курсовая работа (НИР) по теме «Разработка средств автоматического отображения между
таксономиями и проверки их согласованности».

В работе реализовано автоматическое построение соответствий (маппинга) между узлами
двух таксономий, оценка уверенности в найденных соответствиях и проверка
семантической согласованности — как внутри каждой таксономии, так и в построенном
отображении. Пайплайн сравнения, разбор результатов и ограничения — в пояснительной
записке (`note.md`).

## Данные

OAEI 2025 Conference track: семь онтологий (`cmt`, `confOf`, `conference`, `edas`,
`ekaw`, `iasted`, `sigkdd`, от 29 до 140 классов) и 21 эталонный alignment
(только классовые соответствия). Из онтологий берётся лишь иерархия `subClassOf` —
таксономия. Синтетический LLM-прогон использует `cmt`: копирование,
синонимы, переподчинение листа и изменение/добавление атрибутов.
Для обучения GNN синтетика строится по онтологиям обучающих пар.

## Подходы

1. **Эмбеддинги.** Описание узла превращается в вектор bi-encoder'ом, кандидаты
   отбираются по косинусному сходству (top-k). Модели: LaBSE, MiniLM-L6-v2,
   ruRoberta-large, rubert-base.
2. **LLM** (по мотивам LLMs4OM, arXiv:2404.10317). Бинарная классификация пар
   кандидатов в трёх представлениях: C (имя класса), CP (имя + родители),
   CC (имя + дети), а также ансамбль трёх режимов. Модели: `gpt-4.1-mini`,
   `deepseek-v4-flash`. Кандидаты отбираются эмбеддингами, BM25 или объединением
   обоих (см. ablations ниже).
3. **StringEquiv** — нижняя граница OAEI: регистронезависимое совпадение меток.
4. **GraphSAGE** — сиамская графовая сеть на структурных признаках узла
   (отрицательный результат без порога, см. ниже).
5. **Проверка согласованности** (`src/consistency.py`) — целостность таксономии
   (циклы `is-a`, совпадающие метки, несовместимость класса с предком, ссылка на
   отсутствующего родителя, классы без пути к корню) и согласованность отображения
   (инъективность 1:1, противоречие объявленной несовместимости, несохранение
   подчинения, включая отсутствие нужной связи в цели). Низкая уверенность —
   отдельная постобработка, а не семантическая проверка.

## Результаты

Среднее F1 по 21 паре OAEI, посчитанное по кэшу `results/`; для LLM публикуется
ансамбль «не менее двух из трёх» представлений узла (C, CP, CC), для эмбеддинговых
моделей порог уверенности калибруется по схеме leave-one-pair-out, а «лучший режим
на пару» — только верхняя граница, а не результат подхода:

|-------------------------------------------------------|-----------:|
| ruRoberta-large с калиброванным порогом               | 0.677      |
| GNN с калиброванным порогом 0.99                      | 0.667      |
| StringEquiv (baseline)                                | 0.663      |
| MiniLM-L6-v2 с калиброванным порогом                  | 0.653      |
| База для GNN с калиброванным порогом                  | 0.653      |
| rubert-base с порогом 0.95                            | 0.646      |
| LLM + гибридные кандидаты (deepseek-v4-flash)         | 0.645      |
| LaBSE с калиброванным порогом (leave-one-pair-out)    | 0.636      |
| LLM + BM25-кандидаты (deepseek-v4-flash)              | 0.624      |
| LLM + MiniLM-кандидаты (deepseek-v4-flash)            | 0.602      |
| LLM + MiniLM-кандидаты (gpt-4.1-mini)                 | 0.575      |
| LaBSE без порога                                      | 0.360      |
| MiniLM-L6-v2 без порога                               | 0.349      |
| GNN (Siamese GraphSAGE) без порога                    | 0.333      |
| MiniLM без обучения GNN, тот же матчер (`--baseline`) | 0.349      |
| ruRoberta-large без порога                            | 0.299      |
| rubert-base без порога                                | 0.285      |

Разбивка по парам — в `results/comparison.xlsx` (листы по метрикам — F1,
Precision, Recall, True Positives, Predicted, Oracle modes; столбцы — подходы),
полные таблицы и анализ — в `note.md`, раздел 6.
Oracle — выбор режима по эталону самой оцениваемой пары. Лист `Oracle modes`
и колонки `(oracle)` показывают только недоступную при применении верхнюю границу,
не результат развёртываемого метода. GNN-baseline — тот же матчер MiniLM, а не отдельная модель.

Основные наблюдения:

- В абляции MiniLM на 21 паре с `argmax` **имя класса даёт наибольший F1**:
  0.309 против 0.211 у полного описания. Добавление к имени с атрибутами
  совместного блока несовместимостей и комментария снижает F1 с 0.280 до 0.190;
  отдельные эффекты компонентов не изолированы (`make ablation`).
  Это обоснование `name_only` для данной конфигурации, не универсальный запрет на контекст.
- **Исторические генеративные LLM-ансамбли в среднем не обходят строки**: они дают 0.645 (гибридный
  ретривер), 0.624 (BM25), 0.602 (MiniLM-ретривер, DeepSeek) и 0.575
  (MiniLM-ретривер, gpt-4.1-mini) против 0.663 у StringEquiv. Выигрыш — на парах
  с расходящейся лексикой (`cmt` ↔ `conference`: 0.667 у gpt-4.1-mini против
  0.375 у строк, гибридный ансамбль там 0.588), проигрыш — там, где метки
  совпадают дословно (`confOf` ↔ `conference`: 0.667 у гибридного ансамбля
  против 0.737 у строк, у BM25 0.778).
- **Разброс между режимами представления и между ретриверами сопоставим.** У трёх
  конфигураций на DeepSeek средние по режимам различаются на 0.061 (0.559 / 0.603 /
  0.620), ансамбли по ретриверам — на 0.043 (0.602 / 0.624 / 0.645), а внутри
  одной пары размах между режимами доходит до 0.46 (`confOf` ↔ `iasted`).
  Замена обычного MiniLM-ретривера на BM25 даёт 0.602 → 0.624, на гибридный
  (MiniLM ∪ BM25) — 0.602 → 0.645.
- GNN **без порога** даёт 0.333 против 0.349 у MiniLM-базы под тем же
  правилом 1:1. После LOO-калибровки порога порядок средних обратный:
  0.667 против 0.653 (`results/consistency/summary.json`).
  Парного теста нет: значимое превосходство GNN не установлено.
  Различия протоколов (0.314 без свёрток, 0.318 при отложенной онтологии,
  0.345 без синтетики) не доказывают причины результата или бесполезность графа.
- Три повторных прогона одной LLM-конфигурации на двух парах дают размах
  0.217 и 0.044 (`results/llm-variance.json`). Это подтверждает недетерминизм
  режима C, но не оценивает шум среднего по 21 паре или ансамбля и не позволяет
  объявлять различия 0.014–0.06 шумом.
- **Калибровка порога уверенности даёт больше, чем выбор модели.** Без порога
  эмбеддинговый матчер берёт ближайшего кандидата на каждый исходный узел и
  выдаёт 986 пар на 258 эталонных; отсечение по порогу, подобранному на других
  парах (leave-one-pair-out), поднимает F1 LaBSE с 0.360 до 0.636, а
  ruRoberta-large — с 0.299 до 0.677 (лучший эмбеддинговый результат). Единый порог
  между моделями не переносится: калиброванные пороги лежат в диапазонах
  0.70–0.90 (LaBSE), 0.80–0.90 (MiniLM), 0.95 (rubert-base и ruRoberta-large).
- **Средние надо проверять парными тестами.** После поправки Холма на 12
  сравнений значимы только два: превосходство строкового baseline над BM25-LLM
  в среднем по режимам (−0.059, Holm p = 0.013) и эффект порога LaBSE (+0.276,
  Holm p < 0.0001). Разница лучшего LLM-ансамбля и строк не подтверждается
  (−0.018, Holm p = 1.00), как и ruRoberta-large с порогом и строк
  (+0.014, Holm p = 1.00). Пары переиспользуют семь онтологий; их независимость
  не установлена. Тесты ретриверов относятся к средним по режимам, не ансамблям.
- **Проверка согласованности.** После перехода на единое правило отбора
  инъективность 1:1 выполняется в сохранённых отображениях всех подходов, поэтому
  содержательны проверки объявленной несовместимости и несохранения подчинения.
  Например, `cmt#Author ⊑ cmt#ConferenceMember` отображается LaBSE в
  `confof#Author` и `confof#Member`, где нужная связь отсутствует, а не обращена.
  В таблице флагов сравниваются эмбеддинговые результаты без порога по 21 записи с уже
  отфильтрованными LLM по 84 записям (четыре режима) и иным числом матчей.
  Меньшая доля флагов у LLM не доказывает превосходства над калиброванными
  эмбеддингами. Семантический фильтр повышает F1 эмбеддингов без порога на
  0.02–0.07, но снижает LLM на 0.006–0.028; совместный эффект с калиброванным
  порогом не измерен. Ноль флагов таксономии означает только прохождение
  реализованной частичной структурной проверки, не OWL-согласованность.
- **Чувствительность ретривера к бюджету кандидатов.** Гибрид при k = 5
  покрывает 0.927 эталона (потолок F1 0.962), при k = 10 — 0.956 (0.978).
  В LLM-прогоне гибрид имеет до десяти кандидатов, остальные — пять:
  MiniLM recall = 0.783 (потолок 0.878), BM25 = 0.730 (0.844).
  Развёртка k измеряет ретривер, не LLM при разных k. Отбор остаётся
  ограничением, а потолок предполагает precision = 1.0.
- LLM — потенциальное дополнение к StringEquiv, но их сочетание не измерено.
  Уверенность — самооценка в JSON, не вероятность токена «yes/no» из LLMs4OM.
  Резервный эмбеддинговый ответ получает 0.75; доля fallback по кэшу
  невосстановима, и не каждый ответ с 0.75 обязательно резервный.
- Эталон хранится по одному соответствию на источник (последняя связь
  побеждает), хотя исходная разметка допускает n:m. Инъективный выход 1:1
  может не достичь полной полноты такого эталона (подробнее в `note.md`, §3.2).

## Запуск

Нужны Python ≥ 3.14, [uv](https://docs.astral.sh/uv/) и (для `make docx`)
pandoc ≥ 3.0.

```bash
make download        # скачать онтологии OAEI и эталонные alignment'ы
make prepare-data    # OWL -> JSON-таксономии + синтетические вариации
make run-embedding   # эмбеддинговый эксперимент (LaBSE)
make run-string-equiv
make compare-full    # embedding + StringEquiv на всех 21 паре + сводная таблица
make ablation        # абляция режима описания узла и правила отбора пар (MiniLM, ~45 с)
make retrieval       # потолок отбора кандидатов: recall@k для трёх ретриверов
make gnn             # GNN: leave-one-pair-out по 21 паре (GPU, минуты)
make gnn-ontology    # GNN: протокол с полностью отложенной онтологией (7 фолдов)
make gnn-baseline    # GNN: предобученные признаки MiniLM под тем же правилом 1:1.
make consistency     # проверки согласованности, фильтр и развёртка по порогу
make stats           # парные тесты: Вилкоксон, интервалы, поправка Холма
make provenance      # провенанс: константы кода против дат и полей в results/
make test            # юнит-тесты (pytest)
make viewer          # интерактивный просмотрщик таксономий (tkinter)
make viz             # .dot для всех таксономий и пар -> results/viz/
make docx            # note.md -> note.docx
make lint            # ruff
```

LLM-эксперименты требуют ключей и запускаются отдельно: `make run-llm`
(`KODIKROUTER_API_KEY`), `make run-llm-deepseek` (`DEEPSEEK_API_KEY`),
`make run-llm-local` (локальный llama-swap на `127.0.0.1:12434`); `make repeats`
(разброс генерации) тоже платный и требует `DEEPSEEK_API_KEY`. Результаты
кэшируются в `results/`, поэтому повторять их для сборки таблиц не нужно;
`make compare` печатает таблицу прямо из кэша.

## Дополнительный эксперимент Jev

Отдельный эксперимент четвёртого октября 2026 года: `typesafe/jev-1.13` через
[OpenRouter Decisions API](https://openrouter.ai/docs/guides/community/jev),
фактически ответившая версия — `typesafe/jev-1.13-20260917`, провайдер TypeSafe.
Бенчмарк — те же 21 пара Conference и 258 эталонных соответствий.
Канонические кэши не заменяются; эксперимент описан отдельно в разделе 6.5
пояснительной записки и включён в слайды.

`src/runners/jev.py` сохраняет кандидатов существующего `HybridLLMMatcher`:
MiniLM `name_only`, `top_k=5`, `bm25_k=5`, объединение до десяти кандидатов.
Тексты C/CP/CC берутся из `LLMMatcher._describe_concept` без изменений.
В одном запросе передаются описания исходного класса и его кандидатов; для
каждого кандидата задаётся независимый вопрос `Noul` об эквивалентности классов.
Возвращаемое `noul` — вероятность ответа «да», не отдельное поле `confidence`.
Ошибка API останавливает сбор после сохранения попыток, без embedding fallback.

Вероятности всех кандидатов сохраняются **до** отсечения и отбора один-к-одному.
`src/runners/jev_evaluate.py` сначала оставляет вероятности строго выше порога,
затем вызывает `greedy_injective`. LOO-порог выбирается по среднему F1 остальных
20 пар; при равенстве выбирается меньший порог. Ансамбль — прежнее голосование
«не менее двух из трёх» через `ensemble_candidates`; его общий порог выбирается
по F1 ансамбля на остальных парах, отдельно от порогов одиночных режимов.
Сетка порогов: от нуля до 0.95 с шагом 0.05, затем 0.99 и 1.0.

Числа ниже — macro-средние по парам из `results/jev-experiment.json`.
Фиксированный порог 0.7 показывает результат прямого переноса прежнего порога;
LOO — настройка на других парах, не выбор по эталону оцениваемой пары.

| Представление Jev               | F1 при пороге 0.7 | P после LOO | R после LOO | F1 после LOO |
|---------------------------------|------------------:|------------:|------------:|-------------:|
| C: концепт                      | 0.448             | 0.625       | 0.630       | 0.612        |
| CP: концепт и цепочка родителей | 0.287             | 0.697       | 0.706       | 0.690        |
| CC: концепт и дети              | 0.328             | 0.528       | 0.697       | 0.590        |
| Ансамбль с общим порогом        | 0.393             | 0.635       | 0.713       | 0.658        |

В CP все 21 LOO-разбиение выбирают порог 0.25. Совместный выбор представления
и порога на остальных парах тоже выбирает CP в каждом разбиении и даёт F1=0.690.
Это выше средних StringEquiv (0.663), ruRoberta-large с LOO-порогом (0.677)
и прежнего hybrid LLM ensemble (0.645), **но превосходство не подтверждено
парными тестами**: для всех трёх сравнений совместного LOO-выбора `p_holm=1.0`.
Вся новая семья из девяти сравнений корректируется совместно.
Порог 0.7 переносится плохо; он не означает одинакового качества решений у
Jev и генеративной LLM. Ансамбль после LOO уступает одиночному CP по среднему F1.

Сохранённый retrieval содержит 6318 пар-кандидатов на представление, в среднем
5.196 кандидата на исходный класс; в него попали 236 из 258 эталонных
соответствий (pooled recall=0.915). Это не финальная полнота сопоставления.
Для CP pooled-результат после LOO: 176 верных соответствий из 255 предсказаний,
precision=0.690, recall=0.682, F1=0.686. Его macro F1 выше — 0.690.

Стоимость 3648 запросов по `usage.cost` — **$0.129266424**:
3 077 772 входных токена, выходные токены бесплатны; ошибки и повторные
попытки отсутствуют. Отдельная проверка доступа стоила $0.000019530,
всего **$0.129285954**. Медиана длительности запроса — 0.273 секунды,
p95 — 0.367 секунды. Два запуска сбора, включая пилот, заняли около
310 секунд при четырёх одновременно выполняемых запросах, без подготовки
кандидатов и паузы между запусками. Это измерения этого клиента и провайдера,
не доказательство превосходства в скорости над прежним LLM-прогоном.

Проверка вероятностей на всех кандидатах, до отбора: CP Brier=0.0235,
ECE по десяти равным интервалам=0.0477; доля положительных меток и Brier
постоянного отрицательного ответа — 0.0374. Метки задаёт эталон: отсутствующие
в нём соответствия считаются отрицательными. Эти измерения не гарантируют
калибровку на другом домене или правильность отдельного ответа.

Ограничения сравнения: прежние LLM-кэши получены в другое время и не содержат
всех исходных кандидатов, решений до отбора и признаков fallback. Здесь
сохранены прежние алгоритм retrieval, настройки и тексты, но идентичность
старых списков кандидатов проверить нельзя. Инструкция также уточнена:
прежнее «same entity» заменено явной эквивалентностью классов, исключающей
просто связанность и отношение подкласса. Поэтому разницу нельзя приписать
только архитектуре модели. Независимых повторов полного эксперимента нет.

Воспроизведение:

```bash
# Подготовка кандидатов без платных запросов.
uv run --no-sync python -m src.runners.jev prepare
# Сбор только недостающих ответов; нужен OPENROUTER_API_KEY.
uv run --no-sync python -m src.runners.jev collect --max-cost 1 --workers 4
# Полный пересчёт метрик без сети и оплаты.
uv run --no-sync python -m src.runners.jev_evaluate
```

Артефакты: `experiments/jev/manifest.json` — кандидаты, тексты, версии пакетов
и SHA-256 исходных данных; `requests.jsonl` в том же каталоге — все реальные
запросы и ответы без ключа доступа; `api-smoke.json` — отдельная проверка API;
`collection-sources.tar.gz` — точные исходники подготовки и сбора на момент
прогона (после него код форматировался и получил защиту от некорректного
поля `model`). `results/jev-experiment.json` содержит соответствия, пороги,
метрики, калибровку вероятностей, расходы и парные сравнения.
Сбор проверяет сохранённые ответы и не оплачивает их повторно; оценка отвергает
неполный журнал, подменённые запросы/вероятности и изменившиеся исходные данные.
Результаты не попадают в каноническую таблицу `make compare`.
Laya и другие открытые аналоги в этом эксперименте не запускались.

## Структура репозитория

```
src/
  taxonomy.py        структуры данных: TaxonNode, Taxonomy, Alignment, TaxonMatch
  owl_parser.py      OWL -> Taxonomy (owlready2)
  data_loader.py     загрузка OAEI, генератор синтетических таксономий
  prepare_data.py    скрипт: OWL -> JSON, синтетика
  metrics.py         precision/recall/F1 для 1:1- и ranked-соответствий
  consistency.py     проверки целостности таксономий и согласованности отображений
  cache.py           единое описание путей кэша результатов
  matchers/          embedding, llm, string_equiv, gnn, bm25_llm, hybrid
  runners/           эксперименты (compare, consistency, stats, retrieval), сводная таблица
  viz/               GraphViz-рендеринг и интерактивный просмотрщик
data/raw/oaei/       7 онтологий и 21 эталонный alignment (скачиваются)
data/processed/      JSON-таксономии и alignment'ы (генерируются)
results/             кэш результатов по подходам и парам, результаты проверок
note.md              пояснительная записка
note-tables.lua       минимальная ширина колонок численных таблиц при сборке Word
presentation/        презентация (Beamer)
papers/, books/      статьи и книги, на которые опирается работа
```

## Сгенерированные артефакты

В репозитории лежат готовые `note.docx`, `results/comparison.xlsx`,
`presentation/slides.pdf` и `results/viz/`, чтобы их можно было посмотреть
без запуска пайплайна. Они воспроизводятся целями `make docx`, `make compare`,
`make -C presentation` и `make viz` соответственно.

Презентация содержит 23 слайда основного доклада и 14 резервных
слайдов после «Спасибо за внимание» (страницы 24–37 PDF): обзор литературы,
ответы на вопросы и подробности эксперимента Jev. В основной доклад добавлен
слайд с результатами Jev, обновлены итоговая таблица и выводы.
Приложение имеет отдельную нумерацию и не увеличивает счётчик основного доклада.
Для сборки нужен пакет `appendixnumberbeamer` из TeX Live.
